连续汉明码 / 交织 / 采样 2FSK 通信系统
====================================

本次实现范围
------------
1. 连续发送：16 位递增序号、128 位确定性伪随机数据、CRC-16/CCITT-FALSE。
2. 汉明(7,4)编译码，以及深度 1 / 4 / 8 的分组交织和解交织。
   深度 1 表示关闭交织；发射端和接收端必须使用相同深度。
3. 有符号 8 位正弦 FSK 样值、双频点非相干相关能量判决、全部采样相位
   并行搜索同步字、未知起始相位下的接收、每帧结束后重新搜索。
4. 接收端只接收样值和本地 sample_ce，不接收发端起始脉冲、比特边界或序号。
   帧头用于定位帧；64 位训练序列为滑动窗口提供稳定前导。
   32 位同步字同时用于各采样相位的候选搜索。首次匹配后再搜索一整个
   符号周期，以末尾同步符号的频点能量差选择最佳候选采样窗口。
5. 模拟接收启停、随机/突发比特注错、误码与帧统计。

本版本不接入实体 DAC/ADC，不实现独立晶振的采样速率跟踪或射频收发。
未知起始时刻的同步采用同源标称采样率；采样速率发生偏差时的性能待后续扩展。

文件与编译顺序
--------------
1. comm_stream_pkg.vhd         常量、码字顺序、CRC、PRBS、交织映射
2. comm_packet_tx.vhd          逐周期准备数据，持续组帧并生成正弦 FSK
3. comm_sample_rx.vhd          采样相关解调、自主同步与帧体比特输出
4. comm_bit_channel.vhd        解调后、解交织前的可控注错
5. comm_packet_rx.vhd          解交织、逐码字译码、CRC 检查
6. hamming_fsk_stream.vhd      集成、采样使能、诊断统计
7. hamming_fsk_stream_board.vhd 课程 V2 板的时钟、复位、LED 入口
8. tb_comm_codec.vhd           CRC 标准向量、汉明码、交织算法测试
9. tb_comm_stream.vhd          连续收发、注错、统计、接收中断测试
10. tb_comm_sync.vhd           128 个启动偏移、幅度衰减和小幅样值扰动测试

保持 VHDL-93 写法。原来的 hamming_fsk_design.vhd 和
tb_hamming_fsk_link.vhd 没有修改，仍可单独编译验证原始数字闭环。
测试平台和旧设计文件不需要加入 FPGA 综合顶层。

ModelSim 使用
-------------
先把 ModelSim 的工作目录切换到：
D:/modelsimfile/hamming_fsk_compact

自动添加/编译新源码：
    do compile_stream.do

运行并添加深度 8 的主要波形：
    do view_stream.do

运行完整测试集合（最后一个同步扫描可能耗时较长）：
    do run_stream_tests.do

也可以编译后逐个运行：
    vsim work.tb_comm_codec
    run -all
    quit -sim
    vsim -gDEPTH=8 work.tb_comm_stream
    run -all
    quit -sim
    vsim -gPHASE_CASES=8 work.tb_comm_sync
    run -all

完整同步扫描把 PHASE_CASES 改为 128；它遍历一个 128 样点符号内的所有
启动偏移。PHASE_CASES=8 只扫描前 8 个偏移，适合先做短运行。
DEPTH=1、4、8 分别验证关闭交织、深度 4、深度 8。

测试预期（待实际仿真确认）
------------------------
tb_comm_codec：
  “123456789”的 CRC 应为 29B1；1011 的汉明码应为 1010101。
  检查全部 16 种输入及全部单错位置。
  对 4 组不同数据、3 种交织深度、1..10 位突发长度遍历所有合法起点。
  在单次突发长度不超过交织深度时应完全恢复；超出能力时应出现错误。

tb_comm_stream：
  延迟启动接收端；无注错时验证 CRC、伪随机数据、序号和计数。
  在帧体第 70 个比特（从 0 开始）注入连续 4 位错误：
    深度 1 应暴露残留错误；深度 4/8 应纠正并通过 CRC。
  再增加到 16 位突发，确认存在 CRC 失败；随后验证随机注错。
  关闭接收一段时间再开启，检查重新捕获和有效帧之间的序号缺口。

tb_comm_sync：
  一套发送器与一套无发送端提示信号的接收器。
  接收幅度减半，再加 -3..4 的有界整数扰动（不是标定的高斯噪声）。
  128 次启动偏移应各自找到完整帧并正确恢复数据。
  测试平台仅用发端起始脉冲安排受控试验时刻，该信号不进入接收器。

测试遇到 severity error/failure 时应先停止检查，不能只看最后一条 PASS。
run_stream_tests.do 设置 BreakOnAssertion=2，并在断言断点处中止脚本。

帧格式和比特顺序
----------------
物理发送顺序：64 位 0101...训练序列 + 32 位 1ACFFC1D 同步字 + 280 位帧体。
信息帧体：16 位序号（高位先）+128 位数据（高位先）+16 位 CRC（高位先）。
信息帧体共 160 位，切分成 40 个 4 位字，编码为 40 个 7 位汉明码字。
汉明码字内部按向量下标 6..0 发送，校验位的逻辑位置仍为 1、2、4。
交织缓存为 D 行、7 列，每行放一个码字，按列发送。
深度 8 每块 56 位，共 5 块；深度 4 每块 28 位，共 10 块。
解交织写入地址是交织发送地址的逆映射，每次以完整 280 位帧体重新对齐。

CRC：多项式 0x1021，初值 0xFFFF，不反射，最终异或 0。
CRC 只覆盖序号和有效数据。训练序列和同步字不进入编码或交织。

采样和接收
----------
板级 SAMPLE_DIV=32：60.8 MHz /32 =1.9 MSPS。
每符号 128 个样点；0 采用 32 点正弦表步进 1，1 采用步进 2。
两个频点是 59.375 kHz /118.75 kHz，每符号分别 4/8 个载波周期。
符号率 14.84375 ksymbol/s。帧间还有 4 个符号的零值间隔和逐周期准备开销。
testbench 的 SAMPLE_DIV=1 仅加速仿真，不改变样点数或两个频点的比例。

接收端维护 128 样点的滑动相关窗口，计算每个频点的正弦/余弦相关能量。
每个采样相位各有一个 32 位同步搜索历史，不依赖发端的 bit_start。
匹配到候选后，在一个符号周期内选最大能量差的候选；若相等，保留较早者。
随后按该采样相位接收 280 位帧体，再回到搜索状态。
这套实现尚未流水线优化；乘加、能量计算和动态缓存访问的资源及时序需综合确认。

注错参数
--------
error_mode：0 无错误；1 伪随机；2 每帧一次突发；3 伪随机或突发。
random_threshold：0..65535，近似翻转概率为该值 /65536。
独立非零 PRBS 状态用于注错，与数据 PRBS 分开。
burst_start：0..279，从帧体第一个已调制、已解调、仍交织的比特开始计数。
burst_length：0..280，越过帧体结尾的部分被截断，不延伸到下一帧。
以上参数在每次接收同步锁定时锁存，帧内变化不影响正在接收的帧。
改变 INTERLEAVE_DEPTH 是 elaboration generic，需重新加载仿真或重新综合。

统计口径
--------
frames_tx：开始发送的帧数；frames_rx：完成组帧、译码和 CRC 检查的帧数。
crc_error_frames：CRC 失败帧数，仍计入 frames_rx。
raw_bits_checked / raw_bit_errors：实际收到的交织帧体比特及其错误，含注入的错误。
payload_bits_checked / payload_bit_errors：每个已完成接收帧的 128 位有效数据及其错误，
  CRC 失败帧同样计入，不因 CRC 筛选而隐去残留错误。
missing_frames：两个 CRC 正确帧之间的序号缺口，包含未同步和 CRC 失败导致的缺口；
  第一个有效帧之前不统计，不能与 crc_error_frames 直接相加。
syndrome_word_count：非零综合征的码字数，不能解释为“确认纠正成功”的码字数。
sync_acquisitions：接收同步捕获次数。
latency_cycles：本地发端开始发送到对应接收帧完成的时钟周期数。
所有累计计数器为无符号 32 位，自然回绕。
误码率用错误位数除以对应已检查位数；未捕获帧用丢帧统计单独表达。

误码和延迟的精确参考由集成层在同步时捕获本地发端的参考数据，仅进入统计模块。
接收器的同步、解调、纠错和 CRC 均不读取该参考。
external_rx 可以选择外部有符号样值，用于后续扩展或 testbench 扰动。
若外部样值不对应本地发端同一帧，参考误码/延迟计数无意义，应使用独立外部计分器；
接收帧、序号、有效数据和 CRC 输出仍可独立使用。

板级工程
--------
原来的 hamming_fsk_board.qpf 及 quartus_manual/hamming_fsk_lab.qpf 均已引用新增源码，
顶层为 hamming_fsk_stream_board，时钟/复位/16 个 LED 的物理引脚保持原分配。
新的编译输出目录是 advanced_output。原 output_files 中的 SOF 属于旧版本。
本次没有生成新版 SOF，也没有进行板上验证。
默认深度 8，每帧第 70 位开始翻转 4 位。可改板级顶层 generic 选择对照模式。

led_1 的信号数组下标（不等于板子从左到右的排列）：
  0：当前正在接收帧体；1：已经收到过完整帧；2：发生过 CRC 错误；
  3：发生过帧体比特错误；4：发生过译码后有效数据错误；
  5：出现过非零综合征；6：接收帧计数 bit4；7：发送帧计数 bit4。
led_2：最近一帧序号的低 8 位，高位先。
按预期，默认注入可纠正的突发错误时，错误注入和综合征指示应出现，
CRC 错误和译码后有效数据错误指示应保持为 0。需要用户仿真及上板确认。
